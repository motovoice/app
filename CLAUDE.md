# CLAUDE.md

MotoVoice is a push-to-talk voice chat app for motorcycle riders (Expo / React Native, TypeScript). Users create a 24 h voice channel on a self-hostable server ([motovoice/server](https://github.com/motovoice/server)) and invite others via QR code or link. Audio runs over LiveKit (WebRTC). Android + iOS only, no web target.

## Commands

```sh
npm start                    # expo start --clear (needs a dev-client build installed on the device)
npx tsc --noEmit             # type check — the only automated check; there are no tests
npm run clean                # expo prebuild --clean (regenerates android/ and ios/)
npm run build:android        # local EAS dev build (APK)
npm run build:ios            # local EAS dev build
npm run adb:install          # install build-*.apk from the repo root
npm run licenses:generate    # writes src/utils/licenses.generated.json (gitignored, also runs on EAS post-install)
```

- `npm run lint` references eslint, but eslint is not installed or configured. Don't rely on it.
- Expo Go won't work: the app needs native modules (LiveKit WebRTC, notify-kit), so it always runs in an `expo-dev-client` build.
- `android/` and `ios/` are generated by prebuild and gitignored. Native changes go in config plugins (`*.plugin.js`) or `app.config.js`, never in those folders directly.
- A fresh checkout needs `npm run licenses:generate` before `tsc`, because `LicensesModal` imports the generated JSON.

## Release

Pushing a tag `X.Y.Z` (or `X.Y.Z-suffix`, which is a prerelease) triggers [.github/workflows/release.yml](.github/workflows/release.yml). It builds an arm64 APK, an AAB (skipped for prereleases) and an IPA with local EAS builds, then creates a GitHub release with the APK. The app version comes from `APP_VERSION` (set from the tag) in [app.config.js](app.config.js). Secrets: `EXPO_TOKEN`, `ADI_TOKEN`.

## Architecture

```
index.js            entry: notifee background handler + Android foreground-service registration,
                    polyfills, LiveKit registerGlobals(), i18n init, global error → debugLog, then expo-router
app/                expo-router screens (file-based routing, typed routes on)
  _layout.tsx       Stack; on startup loads the saved server URL, password and device id into `api`
  index.tsx         home: display name, server compat check, "rejoin last channel", settings/licenses modals
  create.tsx        POST /api/rooms → shows the QR code, then navigates to /channel as host
  scan.tsx          camera QR scanner → parseInviteUri → join (on the invite's server)
  join.tsx          deep link handler for motovoice://join?room=…&server=… (no UI, just a spinner)
  channel.tsx       the live call: participants, PTT button, connection stats, leave/end channel
src/
  services/api.ts       REST client (module-level state: base URL, password, device id) + invite URI build/parse
  services/storage.ts   all persistence, via expo-secure-store (keys prefixed `motovoice_`)
  services/debugLog.ts  file logger (debug.log in the documents dir, capped at 500k chars, URLs redacted)
  hooks/useLiveKitRoom.ts      Room lifecycle, audio session config, participants, stats, PTT
  hooks/useForegroundService.ts Android foreground service + notification (keeps the mic alive in background)
  hooks/useReconnectSound.ts   loops a sound while LiveKit is reconnecting
  components/           Button, PTTButton, ParticipantCard, ConnectionBadge, Settings/ServerSetup/DebugLog/Licenses modals
  utils/theme.ts        Colors / Spacing / Radius / FontSize / FontWeight tokens (dark theme only)
  locales/{en,de}.json  i18next strings; i18n.ts picks the system language, then applies the saved override
```

### Key flows and conventions

- **Navigation passes call credentials as route params.** `create`, `join`, `scan` and the home "rejoin" all call `router.replace`/`push('/channel', { roomId, server?, livekitToken, livekitUrl, isHost: '1'|'0', hostIdentity, deleteSecret? })`. Booleans are passed as the strings `'1'`/`'0'`. If you add a new way to enter a channel, pass the same params.
- **Server config lives in two places**: persisted in `storage`, and held in memory by `api` (`setBaseUrl`, `setAuthPassword`). Update both whenever the user changes the server (see `ServerSetupModal`, `SettingsModal`). `DEFAULT_API_BASE` is empty, so first launch shows the setup. It can be skipped (`storage.setServerSetupSkipped`) for join-only use; the create button then reopens it.
- **Request headers**: `api.request` adds `X-Server-Password` (when set, on all requests) and `X-Device-Id` (an anonymous random UUID for server-side stats). Room deletion uses `Authorization: Bearer <deleteSecret>`, which only the host gets from `createRoom`.
- **Server compatibility**: `/health` returns `{status, version, authRequired}`. `checkCompatibility` compares it with `extra.minServerVersion` (env `MIN_SERVER_VERSION`, default `1.0.0`). Check it before joining on a server taken from an invite.
- **Server password**: only `POST /api/rooms` needs it. `ServerSetupModal` requires it when `authRequired` is set (skip the setup to only join), `create.tsx` prompts on 401 and saves it, join and scan never ask. Settings can edit it. Older servers still require it on every `/api` call, so join screens show `setup.wrongPassword` on 401.
- **Errors**: non-2xx responses throw `ApiError(status, message)`.
- **Invites**: the QR code holds `motovoice://join?room=<id>&server=<encoded base URL>`. The share link is `<server>/join/<id>`, an HTTP redirect served by the server. An invite never changes the saved server or password: `join`/`scan` pass its server per request and as the `server` route param, `channel` uses it for leave/delete/sharing, and `LastChannel.server` keeps it for rejoin. The configured password is only sent to the configured server.
- **LiveKit**: a custom `LongRetryReconnectPolicy` keeps retrying for 10 minutes, since riders lose signal in tunnels. Participants who leave stay in the list as "ghosts" (`isDisconnected`) for 30 s. The mic starts muted and PTT toggles `setMicrophoneEnabled`. Data saver mode uses `AudioPresets.telephone`, otherwise `speech`. Audio settings are applied when the Room is created, so changes take effect on the next connect.
- **Logging**: use `debugLog.log(level, msg, context?)` (`debug|info|warn|error|fatal`), not `console.log`. LiveKit SDK logs are piped into it too. Users can view and share the log from Settings, so never log tokens or passwords (URLs are redacted automatically).
- **i18n**: every user-facing string goes through `t('section.key')`. Add new keys to **both** `en.json` and `de.json`. Notification text in `useForegroundService` is currently hard-coded English.
- **Imports** use the `@/` alias for `src/` (babel module-resolver + tsconfig paths).
- **Styling**: `StyleSheet.create` with tokens from `@/utils/theme`. No styling library. Aligned key/value formatting is common in this code; match the surrounding file.

### Native / config plugins

- [livekit-setup.plugin.js](livekit-setup.plugin.js) injects `LiveKitReactNative.setup(this)` into Android `MainApplication`.
- [android-manifest.plugin.js](android-manifest.plugin.js) overrides notifee's `ForegroundService` type to `microphone`.
- iOS uses background modes `audio` + `voip`. The audio session is `playAndRecord` with `mixWithOthers` and Bluetooth enabled.
- `expo-adi-registration` reads `ADI_TOKEN` from the env.
